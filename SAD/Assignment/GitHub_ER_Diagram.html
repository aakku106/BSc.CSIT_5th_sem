GitHub Core System - Standard ER Diagram

Entity-Relationship Model with Standard Chen Notation

Standard ER Diagram Components

Entity (Rectangle)

Represents a real-world object or concept (e.g., USER, REPOSITORY). It becomes a table in the database.

Attribute (Ellipse)

Properties that describe an entity (e.g., user_id, repo_name). Key attributes are underlined.

Relationship (Diamond)

Association between entities (e.g., USER "Owns" REPOSITORY). Shows how entities relate to each other.

Primary Key

A key attribute that uniquely identifies an entity occurrence. Represented by an underlined attribute.

Foreign Key

An attribute whose value references a key attribute in another entity, used to connect related data. Example: repo_id in CONTRIBUTOR.

1:N Cardinality

One-to-Many relationship. Example: One USER can own Many REPOSITORIES. Numbers show relationship multiplicity.

M:N Cardinality

Many-to-Many relationship. Multiple records on both sides relate to each other. Example: USER and ORGANIZATION via ORG_MEMBERSHIP.

— Solid Line

Total Participation: Every entity must participate in the relationship (mandatory).

- - Dashed Line

Partial Participation: Entity may or may not participate in the relationship (optional).

Junction Entity

Created to handle M:N relationships by breaking them into two 1:N relationships. Examples: CONTRIBUTOR, ORG_MEMBERSHIP.

Strong vs Weak Entity

Strong Entity: Can exist independently (single border). Weak Entity: Depends on another entity for identification (double border).

Total vs Partial Participation

Total (||): Every instance must participate. Partial (|): Only some instances participate in relationship.
