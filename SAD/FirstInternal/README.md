## 4) Most Probable Questions for Your Exam (Up to 4.1)

- Explain SDLC phases; compare traditional waterfall with prototyping/agile.
- Draw DFD (context + level-0/level-1) for a given system and explain balancing.
- Explain project identification/selection and project initiation/planning process.
- Explain feasibility categories; solve a short economic feasibility or payback/NPV problem.
- Explain requirements determination methods; compare interview/JAD/observation/prototyping.
- Build decision table (or convert problem to structured English/decision tree).
- Explain conceptual data modeling process and draw ER diagram for a given scenario.
- Differentiate process modeling vs data modeling.
- Differentiate logical vs physical database design; explain why physical design matters.
- Explain normalization (at least up to 2NF) with example.
- Explain CASE tools and their role in SDLC.

## 5) One-Day 24 Mark Survival Plan

### Block 1 (3 hours) - Secure Long Question Topics

- SDLC + waterfall issues + prototyping + agile/RAD (one integrated note).
- DFD full practice: 2 complete systems (context + level-0 + one decomposition).
- Feasibility categories + one NPV/payback numerical template.

### Block 2 (3 hours) - Core Analysis/Planning Questions

- Project identification/selection + initiation/planning + baseline project plan.
- Requirements methods: interview, JAD, observation, prototyping, disruptive/radical methods.
- Decision table and decision tree: solve 3 practice scenarios.

### Block 3 (3 hours) - Unit 3.3 and 4.1 Scoring Area

- Conceptual data modeling steps + ER practice (retail/student-type scenario).
- Logical vs physical DB design (clear comparison table).
- Normalization to 2NF with one worked example.

### Block 4 (2 hours) - Final Exam-Focused Revision

- Prepare 12 short-answer bullets (definition + 4 points each).
- Memorize 3 standard answer frameworks:
  - Feasibility framework: technical, economic, operational, schedule.
  - Project planning framework: identify, select, initiate, plan, baseline.
  - DB framework: conceptual model -> ER -> relation -> normalization -> physical design.

## 6) Exam Attempt Strategy for 24 Marks

- In long questions, attempt the two safest from: DFD, SDLC/prototyping/agile, feasibility/NPV, ER+conceptual modeling.
- In short questions, prioritize direct-theory questions first: project planning, CASE, requirements methods, logical vs physical DB, normalization, decision table/tree.
- For diagram questions, always draw neat labeled diagrams first, then explain.
- For compare/differentiate questions, write in table form to save time and increase clarity.
- For numericals, write formula first, then substitution, then final interpretation.
